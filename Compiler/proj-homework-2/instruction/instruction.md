# 大作业 2of2 实验指导书：简易编译器 QCompiler 实现及验证 [cite: 1, 2]

本实验完整复现现代编译器词法分析→语法分析→AST生成→中间代码生成→目标代码生成→代码优化全流程，基于自定义QL语言、QTAC 中间表示，最终输出 ARM 汇编并在鲲鹏平台验证运行，覆盖编译原理核心技术点。[cite: 3]

---

## 一、实验基本信息 [cite: 4]

* **实验名称**：简易编译器 QCompiler 实现及验证 [cite: 5]
* **适用对象**：计算机相关专业编译原理课程 [cite: 7]
* **源语言**：自有QL 语言 [cite: 8]
* **中间语言**：自有QAST 抽象语法树、自有QTAC 语言 [cite: 9]
* **目标架构**：ARM64(华为鲲鹏) [cite: 10]

---

## 二、实验目的 [cite: 11]

* 本实验通过理论与实践结合，掌握编译程序完整实现要点，包括词法分析、语法分析、抽象语法树、符号表、中间表示、运行时环境、目标代码生成、优化。[cite: 12]
* 本实验将编译原理与编译器工程实现相衔接，通过理论落地来加强理论知识的融会贯通和抽象能力提升。[cite: 13]
* 运用 AI 辅助完成QL 语言简易编译器的设计和代码实现，提升工程能力。[cite: 14, 15]
* 编程实现编译器全流程逻辑，使用qsort 测试程序验证各阶段输出。[cite: 16, 18]
* 在华为鲲鹏ARM环境完成汇编、链接、运行，验证目标代码正确性。[cite: 17, 19]

## 四、实验原理 [cite: 42]

### 1. 编译器整体架构 [cite: 43]

* QL 源程序 [cite: 44]
  * ↓【词法分析】 [cite: 45]
* Token 流 [cite: 46]
  * ↓【语法分析LL(1)/SLR(1)】 [cite: 47]
* QAST 抽象语法树 [cite: 48]
  * ↓【中间代码生成】 [cite: 49]
* QTAC 三地址代码、符号表 [cite: 50]
  * ↓【-DFA+代码生成】 [cite: 51]
* ARM64汇编代码 [cite: 52]
  * ↓【代码优化】 [cite: 53]
* 优化后ARM64汇编 [cite: 54]
  * ↓【汇编+链接+运行】 [cite: 55]
* 鲲鹏平台可执行程序 [cite: 56]

### 2. 核心技术 [cite: 57]

* **词法分析**：正则表达式、状态机、Token切分与类型标记 [cite: 58]
* **语法分析**：LL(1) 递归下降、SLR (1)表驱动分析 [cite: 59]
* **语义及中间表示**：QAST结构设计、QTAC三地址码 [cite: 60]
* **代码生成**：-DFA状态机、Q2ARM 模板映射 [cite: 61]
* **代码优化**：局部优化+寄存器分配 [cite: 62]
* **系统运行**：ARM64汇编、静态链接、鲲鹏环境执行 [cite: 63]

## 五、实验内容与步骤 [cite: 64]

* **任务步骤1：词法分析器实现（ABC公用）** [cite: 65]
  * 定义QL语言关键字、标识符、常量、运算符、界符 [cite: 66]
  * 构建词法规则，实现DFA或正则匹配 [cite: 67]
  * 输入QL程序，输出：(类型,值)格式 Token序列 [cite: 68]
  * 测试用例：`qsort.ql` → `tokens.txt` [cite: 69]
* **任务步骤2A：LL(1) 递归下降分析（仅A）** [cite: 70]
  * 对QL文法提取左公因子、消除左递归 [cite: 71]
  * 构造 SELECT集，验证LL(1)合法性 [cite: 72]
  * 为每个非终结符编写递归下降分析函数 [cite: 73]
  * 输入Token流，构建并输出QAST [cite: 74]
* **任务步骤2B：SLR (1) 分析框架（仅B）** [cite: 75]
  * 增广文法，构造LR(0)项目集规范族 [cite: 76]
  * 构造 SLR (1)分析表(ACTION/GOTO) [cite: 77]
  * 实现表驱动移进归约分析程序 [cite: 78]
  * 生成QAST 抽象语法树 [cite: 79]
* **任务2AB：AST遍历生成QTAC** [cite: 80]
  * 设计 QAST 结点结构(表达式、语句、函数、控制流) [cite: 81]
  * 实现前序/后序遍历，执行语义动作 [cite: 82]
  * 输出标准 QTAC三地址代码和符号表 [cite: 83]
* **任务步骤2C：SLR (1)制导翻译（仅C）** [cite: 84]
  * 增广文法，构造LR (0)项目集规范族 [cite: 85]
  * 构造 SLR (1)分析表(ACTION/GOTO) [cite: 86]
  * 实现表驱动移进归约分析框架 [cite: 87]
  * 在SLR (1)分析过程中嵌入语义规则 [cite: 88]
  * 移进归约时直接生成QTAC和符号表 [cite: 89]
  * 跳过QAST阶段，实现源语言到中间代码直接翻译 [cite: 90]
* **任务步骤3：QTAC→ ARM64 汇编生成（ABC公用）** [cite: 91]
  * 利用 QTAC 到ARM的指令模板Q2ARM构建-DFA指导寄存器选择与指令编排 [cite: 92]
  * 实现代码生成器，输出.s汇编文件 [cite: 93]
  * 处理函数调用、内存访问、控制流跳转 [cite: 94]
* **任务步骤4：ARM汇编代码优化（任意步骤任选）** [cite: 95]
  * 复制传播优化 [cite: 96]
  * 无用指令(死代码)删除 [cite: 97]
  * 公共子表达式消除 [cite: 98]
  * 叶子函数优化(省去栈帧) [cite: 99]
  * 图着色寄存器分配 [cite: 100]
  * 输出优化后的ARM汇编 [cite: 101]
* **任务步骤5：整体测试与鲲鹏验证（ABC公用）** [cite: 102]
  * 使用qsort 测试全编译器链路：QL → Token → AST (仅AB) → QTAC → ARM → opt_ARM [cite: 103, 104]
  * 在鲲鹏平台执行汇编与链接：[cite: 105, 106, 107]

    ```bash
    as -o qsort.o qsort.s
    ld -o qsort qsort.o
    ```

  * 运行程序，验证排序功能正确性 [cite: 110]
  * 记录各阶段输出文件与运行结果 [cite: 111]

## 七、实验注意事项 [cite: 125]

* 实验任务分为A、B和C三种，任选一种完成即可。[cite: 126]
* 优化子任务为任选，包括任务步骤5中给出的几个优化遍。[cite: 127]
* 如果没有选寄存器分配则需要手工替换ARM 代码中的虚拟机寄存器为物理寄存器。[cite: 128, 129]
* 对QCompiler 的实现语言不做限制。[cite: 130]
* 对QL 文法做必要的修剪或定义额外的冲突消解规则以满足 LL (1)/SLR(1)分析的条件。[cite: 131, 132]
* Token 定义必须统一，避免语法分析出错。[cite: 133]
* QAST 结点设计要覆盖所有语法结构。[cite: 134]
* ARM64 调用约定、寄存器使用必须规范。[cite: 135]
* 鲲鹏平台必须使用原生ARM工具链汇编链接。[cite: 136]
* 优化必须保证语义不变，不能破坏程序功能。[cite: 137]
